# Tracker + voice companion v2 (Nov 12, 2026)


## Install (upgrading from v1)
Unzip `poe_voice_bundle.zip` over the old folder (keep `voice\.venv` and `voice\config.json`), then run
`voice\setup.bat` again **or** `voice\.venv\Scripts\python.exe -m pip install -r voice\requirements.txt`.

New pip requirements:
- `Pillow>=10` (screen grab + pasted image decode)
- Windows only, for the built-in Windows OCR: `winrt-runtime`, `winrt-Windows.Media.Ocr`, `winrt-Windows.Graphics.Imaging`,
  `winrt-Windows.Storage.Streams`, `winrt-Windows.Foundation`, `winrt-Windows.Globalization` (all `>=2.0`)
- Optional (commented out): `rapidocr-onnxruntime>=1.3` as a fallback OCR engine
- Research uses only the Python standard library (urllib). Optional: set the `OPENAI_API_KEY` user environment variable.

## What changed
1. **Multi-field defence dictation.** One sentence can set level, fire, cold, lightning, chaos, life, ES, pool, EHP, max hit and block
   ("level 12, 37 cold res, 45 fire, 28 lightning, 25 chaos", "res are 76 75 75", "cold 25, 0 everything else",
   "lightning 48, everything else capped"). Numbers and keywords pair in either order. One readback names every field and lists
   what's uncapped. Life and ES are stored separately and pool = life + ES. "Life in energy shield 512" (a Whisper mishearing) means pool.
   Ele "capped" is derived from the three numbers.
2. **Screenshot import.** Press F10 (listen-only, configurable), say "scan my defences", or paste a screenshot into the tracker.
   The local OCR engine is Windows.Media.Ocr, falling back to rapidocr. It reads the in-game Defences tab or the PoB sidebar
   ("75% (82%)" = 82 uncapped; PoB "75% (+12%)" = 87).
   The tracker shows a proposal, and nothing applies until "confirm" or Apply. "discard" drops it and "undo" reverts it.
3. **Kitava penalties.** −30 after A5 and −60 after A10, taken from the milestones and shown in the Defense panel.
   Dictated or scanned numbers are treated as in-game (penalty already included), and the readback says "after Kitava penalty minus 30".
   If res was entered before a Kitava milestone, the milestone readback warns (triple beep) "res dropped 30 … tell me your new res".
   The Defense panel and Next up show a warning, and the gates fail until new numbers arrive. Nothing is silently subtracted.
4. **Pause/resume** by voice ("pause timer", "taking a break", "resume", "I'm back") or the ⏸ button.
   Paused time is excluded from elapsed, segment timers, pace deltas, targets and the Kitava projection.
   A big PAUSED banner shows, plus PAUSED in the header. The state survives a reload. Marking a milestone auto-resumes.
5. **Build plan panel** replaces the Build/Bar dropdowns (the Build select moved to Character).
   It is driven by `plan/necro/build_plan.json`: 7 stages from Ziz's PoBs (A1 Rolling Magma → SRS → Absolution → Vaal Absolution maps → Frostbearer).
   The panel shows "link now" for your act and level, link counts 2L–6L, aura/movement/utility groups, weapon swap, spectres and notes,
   and you can browse other stages. The bar is derived from the plan (relaxed/minion).
   Link questions are answered locally in ~10 ms, using the level and act in the question if given, otherwise the tracker.
6. **Local Q&A.** Answers questions about res, a trigger item ("what should I do with a Cane"), next, pace (incl. played time), gate, Fate rules
   and mic check. Unknown questions become a note, and the readback suggests "say research …".
   Questions mixed with statements are split ("Act 5 done, what are my res?" marks the act AND answers).
7. **Research.** Triggered only by "research X", "look up X" or "wiki X". You get an immediate spoken "Looking up X."
   It reads the poewiki MediaWiki API (search → intro extract → rendered infobox → wikitext Version history) and then calls the LLM.
   The default backend is OpenAI-compatible (`https://api.openai.com/v1`, model `gpt-6-luna`, key from env `OPENAI_API_KEY`, never stored).
   The prompt is grounded only in the wiki text and tracker state, with an 8 s budget.
   On any failure, timeout or missing key it falls back to the poewiki summary. It speaks 1–3 sentences and posts the full answer plus the poewiki link to History.
   It says when the page has no 3.30 info. "never mind" cancels and "repeat that" re-reads.
   `companion.py --check-llm` tests the key without printing it. Ollama and none backends are kept.
8. **Fates.** "Going to try Mervail with 1 Fate" checks the cap (triple beep if over) instead of logging a kill. Kill readback works.
9. **Bandits** ("killed Oak", "helped Alira", "killed all bandits") are logged.
10. **Undo** covers every new command (defence batch, pause, resume, Kitava stale flag, OCR confirm/proposal, research entry, fate attempt).
    The page's ⏸ and Apply/Discard buttons go through the same undoable path.
11. **Near-death fix** (see below). Voice state is saved synchronously before the readback, and pending saves flush on page hide.

## The double near-death ("second in 30 minutes")
- A single voice command never produced two entries in any reproduction: one tab, two tabs, a reload in the middle of a command,
  and the same command id delivered three times (incl. across a reload). The parser also merges "near death … almost died" into one action.
- The readback is computed when the command is applied, from the entries already in the log. So "second" means another near-death entry
  was already there from the same moment: most likely the Near-death quick button or the Drops box, or the event said twice in two utterances.
- Real bug found along the way: a reload within the 150 ms save debounce lost the voice entry.
- Fixes:
  - Near-deaths within 90 s now count as **one incident**. The second entry is badged "same incident" and the readback says so.
  - Two separate incidents in 30 min still trigger the stop rule.
  - Voice commands are persisted before answering, so a reload can't lose or double-apply one.
  - Regression tests cover all of this.

## New config options (voice/config.json)
- `ocr_hotkey` ("f10", "" = off)
- `ocr_engine` ("auto" | "windows" | "rapidocr")
- `ocr_region` ("left" | "full" | [x, y, w, h] fractions)
- `research.backend` ("openai_compatible" | "ollama" | "none")
- `research.openai_compatible.{base_url, model, api_key_env, max_tokens, token_param, temperature}`
- `research.ollama.{base_url, model}`
- `research.{llm_timeout_s 8, wiki_timeout_s 4, max_spoken_chars 260, wiki_api}`

New CLI flags: `--check-llm`, `--research "question"`, `--ocr-file shot.png`.
